# مرجع ماژول کش (`parsikit.cache`)

زیرساخت کشینگ حافظه‌ای با کارایی بالا و ایمن در برابر چندریسمانی (Thread-safe) برای محاسبات پرهزینه عددی و زبانی.

---

## ۱. معرفی و کاربرد

ماژول `parsikit.cache` سازوکار کشینگ مبتنی بر الگوریتم شبه-LRU را فراهم می‌کند که به صورت داخلی در توابعی با بار پردازشی تکراری نظیر تبدیل اعداد بسیار بزرگ به حروف (`parsikit.number.number_to_words`) مورد استفاده قرار می‌گیرد.

> **نکته درباره پایداری ماژول:** این ماژول در درجه اول یک ماژول زیرساختی (Internal Infrastructure) برای خود کتابخانه است. با این حال کلاس‌ها و دکوراتورهای آن پایدار و در پروژه‌های شما نیز به صورت مستقل قابل استفاده هستند.

---

## ۲. کلاس‌ها

### `ThreadSafeLRUCache`

```python
class ThreadSafeLRUCache:
    def __init__(self, maxsize: int = 1024) -> None
```

کش سبک و محافظت‌شده با قفل بازگشتی `threading.RLock` در حافظه رم جهت جلوگیری از بن‌بست در فراخوانی‌های تو در تو و بازگشتی.

#### اعتبارسنجی ظرفیت:
- آرگومان `maxsize` باید عدد صحیح (`int`) باشد. مقادیر غیرصحیح خطای `TypeError` تولید می‌کنند.
- مقدار `maxsize` باید بزرگتر یا مساوی صفر باشد (`maxsize >= 0`). اعداد منفی خطای `ValueError` ایجاد می‌کنند.
- مقدار `maxsize = 0` به عنوان **حالت بدون ذخیره‌سازی (no-storage)** عمل کرده و هیچ مقداری را ذخیره نمی‌کند.

#### متدها و ویژگی‌ها:
- **`get(key: Any, default: Any = None) -> Any`**: مقدار کلید را بازمی‌گرداند و جایگاه کلید را در لیست دسترسی‌های اخیر به عنوان تازه‌ترین (MRU) به‌روزرسانی می‌کند. در صورت عدم وجود، مقدار `default` را می‌دهد.
- **`set(key: Any, value: Any) -> None`**: مقدار را ذخیره یا به‌روزرسانی می‌کند. در صورتی که کلید از قبل موجود باشد، بدون حذف آیتم‌های دیگر، مقدار آن به‌روز شده و به تازه‌ترین جایگاه منتقل می‌شود. در صورت تکمیل ظرفیت، قدیمی‌ترین آیتم بدون استفاده (LRU) حذف می‌گردد.
- **`clear() -> None`**: کل مقادیر کش را پاکسازی کرده و آمارهای Hit و Miss را صفر می‌کند.
- **`pop(key: Any, default: Any = ...) -> Any`**: کلید مشخص‌شده را حذف و مقدار آن را برمی‌گرداند. در صورت عدم وجود کلید و عدم ارسال پیش‌فرض، `KeyError` صادر می‌کند.
- **`keys_order`**: فهرستی از کلیدهای ذخیره‌شده را به ترتیب از قدیمی‌ترین (LRU) تا تازه‌ترین (MRU) برمی‌گرداند.
- **`__len__()` و `__contains__(key)`**: پشتیبانی از پروتکل‌های استاندارد پایتونی نظیر `len(cache)` و `key in cache`.

## ۳. دکوراتورها

### دکوراتور `@memoize`

```python
from parsikit.cache import memoize

@memoize(maxsize=1024)
def my_func(a, b):
    ...
```

دکوراتور پایتونی برای به خاطر سپردن (Memoization) خروجی توابع خالص به ازای ورودی‌های مشخص.

#### قابلیت‌های کلیدی:
1. **هماهنگی با پیکربندی سراسری:** وضعیت `parsikit.config.enable_cache` را بررسی می‌کند. اگر روی `False` باشد، کش را دور می‌زند و مستقیماً تابع اصلی را فراخوانی می‌کند.
2. **ایمنی در محیط‌های چندنخی و توابع بازگشتی:** با استفاده از `threading.RLock` تضمین می‌کند که دسترسی‌های همزمان چند ریسمان و همچنین توابع بازگشتی بدون خطر بن‌بست (Deadlock) اجرا شوند.
3. **تفکیک دقیق مقادیر None و مقادیر تهی:** با استفاده از نگه‌دارنده درونی (Sentinel)، تمایز کامل میان مقدار بازگشتی `None` یا مقادیر Falsey با خطای Cache Miss تضمین می‌شود.
4. **رفتار هوشمند در برابر آرگومان‌های Unhashable:** چنانچه آرگومان‌های تابع شامل لیست، دیکشنری، مجموعه یا ساختارهای غیرقابل هش باشند، به جای ایجاد خطای `TypeError`، کش به صورت خودکار دور زده شده و تابع با موفقیت اجرا می‌شود.
5. **حفظ هویت شیء (Object Identity):** اشیای کش‌شده بدون کپی عمیق غیرضروری و به صورت ارجاع بازگردانده می‌شوند.
6. **ابزارهای بازرسی و مدیریت:** تابع دکوریت‌شده خصوصیات زیر را در اختیار برنامه‌نویس قرار می‌دهد:
   - `func.cache`: ارجاع به نمونه `ThreadSafeLRUCache`.
   - `func.cache_clear()`: پاکسازی کش و ریست کردن آمار.
   - `func.cache_info()`: گزارش وضعیت شامل hits، misses، maxsize و currsize.

#### مثال کاربردی:

```python
import parsikit
from parsikit.cache import memoize

@memoize(maxsize=256)
def calculate_vat_report(invoice_id: int, rate: float = 0.10) -> dict:
    # محاسبات سنگین دیتابیسی یا ریاضی
    return {"id": invoice_id, "tax": 150000}

# فراخوانی اول تابع را اجرا کرده و خروجی را کش می‌کند
result1 = calculate_vat_report(1024)

# فراخوانی دوم بلافاصله از حافظه رم برگردانده می‌شود
result2 = calculate_vat_report(1024)
assert result1 is result2

# مشاهده آمار کش
info = calculate_vat_report.cache_info()
print(f"Hits: {info.hits}, Misses: {info.misses}")

# پاکسازی کش
calculate_vat_report.cache_clear()

# خاموش کردن موقت کش
parsikit.config.enable_cache = False
result3 = calculate_vat_report(1024)  # تابع مجدداً اجرا می‌شود
parsikit.config.reset_defaults()
```

## ۴. نکات و محدودیت‌ها

- **آرگومان‌های غیرقابل هش (Unhashable):** ارسال لیست یا دیکشنری باعث پرتاب خطای `TypeError` نمی‌شود، بلکه تابع به صورت مستقیم اجرا شده و کش دور زده می‌شود.
- **نتایج تغییرپذیر (Mutable):** از آنجا که اشیاء با ارجاع کش می‌شوند، تغییر در خروجی دریافتی (مانند تغییر مقدار درون دیکشنری بازگشتی) در نسخه‌های بعدی فراخوانی نیز منعکس می‌گردد مگر اینکه مصرف‌کننده از آن کپی تهیه کند.
- **ایزولاسیون پردازه‌ها:** کش در سطح حافظه رم یک پردازه عمل می‌کند و در مدل چندپردازه‌ای (مانند چندین Worker در Gunicorn) هر پردازه کش مستقل خود را دارد.
