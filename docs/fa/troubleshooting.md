## ۱. خطای `SyntaxError` هنگام اجرا در پایتون ۳.۱۰ یا ۳.۱۱

### علت
در نسخه‌های پایتون قبل از ۳.۱۲، استفاده از بک‌اسلش (`\`) درون بخش عبارات f-string غیرمجاز بود (طبق مشخصه PEP 701 که در پایتون ۳.۱۲ اضافه شد). در نسخه v3.3.0 پارسی‌کیت یک مورد در `parsikit.dev.debug_text` وجود داشت که باعث می‌شد پایتون‌های ۳.۱۰ و ۳.۱۱ نتوانند پکیج را ایمپورت کنند.

### راه‌حل در نسخه ۳.۳.۱
این مشکل در نسخه ۳.۳.۱ به طور کامل رفع شده است. برای حل مشکل، پارسی‌کیت را به نسخه ۳.۳.۱ ارتقا دهید:
```bash
pip install --upgrade parsikit
```

## ۲. اعداد در خروجی یا ترمینال به شکل علامت سوال یا کاراکترهای عجیب نمایش داده می‌شوند

### علت
ترمینال یا شبیه‌ساز کنسول شما از کدگذاری UTF-8 پشتیبانی نمی‌کند یا متغیر محیطی `PYTHONIOENCODING` به صورت پیش‌فرض روی `ascii` تنظیم شده است (به‌خصوص در ویندوزهای قدیمی).

### راه‌حل
متغیر محیطی UTF-8 را در ابتدای اجرای اسکریپت یا در تنظیمات محیط تنظیم کنید:

در لینوکس/مک:
```bash
export PYTHONIOENCODING=utf-8
```

در پاورشل ویندوز:
```powershell
$env:PYTHONIOENCODING="utf-8"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

در ابتدای کد پایتون:
```python
import sys
if sys.stdout.encoding != "utf-8":
    import io
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")
```

## ۳. خطای `InvalidNationalCodeError` برای کدهایی که ۱۰ رقم دارند

### علت
صرف ۱۰ رقمی بودن برای معتبر بودن کد ملی کافی نیست. کدهای ملی ایران دارای شرایط زیر هستند:
1. ارقام تکراری پشت سر هم نامعتبرند (مثل `1111111111` یا `0000000000`).
2. رقم دهم باید با الگوریتم باقیمانده مجموع حاصل‌ضرب ضرایب ارقام بر ۱۱ (چک‌سام ثبت احوال) مطابقت داشته باشد.

### مثال و بررسی
```python
import parsikit

# کد تستی با رقم کنترل نادرست خطا می‌دهد:
try:
    nc = parsikit.NationalCode("0010123451")
except parsikit.InvalidNationalCodeError as e:
    print(f"کد نامعتبر است: {e}")

# اما اگر کد کنترل صحیح باشد (برای پیش‌شماره 001012345 رقم کنترل 8 است):
nc = parsikit.NationalCode("0010123458")
print(nc.is_valid)  # True
print(nc.location)  # {'province': 'تهران', 'city': 'تهران مرکزی'}
```

## ۴. به‌هم‌ریختگی نیم‌فاصله‌ها در رندر گرافیکی (PIL / OpenCV / ReportLab / Matplotlib)

### علت
موتورهای گرافیکی پایتون به صورت پیش‌فرض از الگوریتم دوجهته یونیکد (BiDi) و شکل‌گیری حروف متصل عربی/فارسی پشتیبانی نمی‌کنند؛ در نتیجه حروف فارسی به صورت جدا از هم و از چپ به راست رسم می‌شوند.

### راه‌حل
از ماژول بازآرایی (`parsikit.reshaper`) استفاده کنید:
```python
import parsikit

raw_text = "پردازش متن فارسی"
reshaped_text = parsikit.reshape_for_graphics(raw_text)

# اکنون متن آماده ارسال به موتور رسم تصویر یا PDF است:
# draw.text((x, y), reshaped_text, font=font)
```

اگر متن شما چندخطی است، از `reshape_paragraph_for_graphics` با تعیین حداکثر طول سطر استفاده کنید.

## ۵. اختلاف یک روز در تاریخ اسفند یا سال‌های کبیسه جلالی

### علت
در تقویم هجری شمسی، سال‌های کبیسه بر اساس دوره‌های نجومی ۳۳ ساله و ۲۸ ساله تعیین می‌شوند و سال ۳۶۶ روزه است (روز ۳۰ اسفند معتبر است). در نسخه‌های پیش از ۳.۳.۱ فرمول کبیسه در برخی سال‌ها جابه‌جا محاسبه می‌شد.

### راه‌حل در نسخه ۳.۳.۱
در نسخه ۳.۳.۱ تابع `is_jalali_leap` با محاسبات تقویم نجومی و الگوریتم خورشیدی هماهنگ شده است:
```python
import parsikit

print(parsikit.is_jalali_leap(1399))  # True (کبیسه)
print(parsikit.is_jalali_leap(1400))  # False (۳۶۵ روزه)
print(parsikit.is_jalali_leap(1403))  # True (کبیسه)
print(parsikit.is_jalali_leap(1404))  # False (۳۶۵ روزه)
```

## ۶. ماسک کردن مقادیر بسیار کوتاه یا نامعتبر

### سوال
اگر رشته ورودی به توابع `mask_mobile` یا `mask_card` کمتر از طول استاندارد باشد، چه اتفاقی می‌افتد؟

### پاسخ
در نسخه ۳.۳.۱، توابع ماسک‌گذاری به شکل ایمن عمل می‌کنند؛ اگر ورودی کوتاه‌تر از آن باشد که بخش میانی آن ماسک شود، مقدار به شکل ستاره‌دار برگردانده می‌شود تا هیچ داده حساسی در لاگ‌ها افشا نگردد.

```python
import parsikit

print(parsikit.mask_mobile("0912"))  # '****'
print(parsikit.mask_card("6037"))    # '****'
```
