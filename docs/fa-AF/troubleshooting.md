# رهنمود رفع مشکلات و عیب‌یابی (Troubleshooting)

راهکارهای رفع مشکلات متداولی که امکان دارد حین استفاده از ParsiKit رخ دهد:

---

## ۱. بروز خطای SyntaxError در پایتون 3.10 و 3.11

### علت مشکل
قبل از پایتون 3.12، قرار دادن کاراکتر اسلش وارونه (`\`) در داخل بخش‌های عبارتی f-string توسط دستور زبان پایتون مجاز نبود (PEP 701). در نسخه‌ی v3.3.0 در یک سطر از تابع `debug_text` چنین عبارتی وجود داشت که در پایتون 3.10 و 3.11 موجب بروز خطا می‌شد.

### راهکار
این مورد در نگارش v3.3.1 به گونه‌ی کامل رفع گردیده است. کتابخانه را به v3.3.1 ارتقا دهید:
```bash
pip install --upgrade parsikit
```

## ۲. نمایش ناخوانا یا علامت سوال حروف در ترمینال

### علت مشکل
هنگامی که رمزگذاری (Encoding) خروجی خط فرمان روی UTF-8 تنظیم نشده باشد، حروف فارسی و دری ممکن است به صورت علامت سوال یا نویسه‌های نامفهوم نمایش داده شوند.

### راهکار
رمزگذاری محیط را روی UTF-8 تنظیم نمایید:

در لینوکس و مک (Linux/macOS):
```bash
export PYTHONIOENCODING=utf-8
```

در پاورشل ویندوز (Windows PowerShell):
```powershell
$env:PYTHONIOENCODING="utf-8"
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

## ۳. جدا افتادن یا معکوس شدن حروف در Pillow یا OpenCV

### علت مشکل
موتورهای رندر ۲بعدی به گونه‌ی پیش‌فرض چینش حروف متصل عربی و الگوریتم دوجهته‌ی یونیکد (BiDi) را پشتیبانی نمی‌کنند و کلمات را از چپ به راست و با حروف گسسته رسم می‌نمایند.

### راهکار
از ماژول بازآرایی ParsiKit استفاده کنید:
```python
import parsikit

raw = "پروسس تصویر"
reshaped = parsikit.reshape_for_graphics(raw)
# رشته‌ی reshaped را به تابع رسم تصویر بدهید
```

## ۴. پرتاب استثنای `InvalidNationalCodeError` برای ورودی ۱۰ رقمی

### علت مشکل
یک عدد ۱۰ رقمی اگر دارای ویژگی‌های زیر باشد پذیرفته نمی‌شود:
۱. تمام ارقام آن یکسان باشد (مانند `1111111111`).
۲. رقم دهم آن با باقیمانده‌ی الگوریتم ریاضی تقسیم بر ۱۱ (چک‌سام) مطابقت نداشته باشد.

### راهکار
مطمئن شوید که دیتای ورودی بر بنیاد الگوریتم ریاضی دارای رقم کنترلی معتبر است (مثلاً برای ارقام ابتدایی `001012345`، رقم چک‌سام درست `8` می‌باشد: `0010123458`).
